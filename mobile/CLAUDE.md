# Stitch mobile

Android companion for the Stitch desktop studio (this repo's root, `..`). The phone is a **remote**: every chat, story, character and generation runs on the PC and stays in its library. The phone can also **generate text, images and voice on-device** (Qualcomm NPU via QNN, GPU, or CPU); those results upload to the PC library too.

## How it works
- **Same UI as desktop.** The web layer reuses the desktop renderer source directly: Vite aliases `@/` → `../src/renderer/src` and `@shared/` → `../src/shared` (override with `STITCH_DESKTOP`). Pages, components, stores and styles are the desktop's; phone layouts are `max-md:` variants / `useCompact()` in the desktop code. Features added on desktop appear here automatically. `@mobile/` → this project's `src/`.
- **Bridge** (`src/bridge/`): `install.ts` sets `window.stitch` (the same bridge the Electron preload provides) **before** any desktop module loads. `connection.ts` is one WebSocket to the PC (`<endpoint>/api/ws`, token auth, ping/pong). A pairing holds endpoint base URLs — LAN `http://ip:47847`, Tailscale IP, and the PC's public "Access from anywhere" address (`https://…trycloudflare.com` / `https://<pc>.ts.net[:port]` / custom). It cycles through them, asks the PC's encrypted relay (`pairing.ts relayLookup`, ntfy.sh topic + AES-GCM key from pairing) after each failed round (the Cloudflare address changes when the PC restarts), and hops back to Wi-Fi when it's reachable again (`preferLocal`). `router.ts` routes every `invoke`: `override(channel, fn)` answers on the phone (return `PASS` to fall through to the PC), `merge(channel, fn)` post-processes PC results, `emitLocal` fires events. `system.ts` handles `sys:*` (phone file picker → upload to PC; PC folder browser; exports saved on the PC, offered to the share sheet). `media.ts` rewrites `stitch://` URLs to the PC's media server (`/api/f`, `/api/t` thumbnails, `/api/wp` wallpapers) — the desktop calls it through `fileUrl`/`thumbUrl`/`resolveUrl`.
- **PC side** lives in the desktop app at the repo root: `src/main/remote/` (server, pairing, devices, files) and Settings → Phone (`features/settings/PhoneSettings.tsx`). Pairing: QR (`stitch://pair?d=…`) or 6-digit code + PC address.
- **Shell** (`src/shell/`): top bar, floating tab bar (`nav.tsx`), drawer (the desktop `Sidebar`), More sheet, `JobDock` (mini-player style generation bar), `LinkStatus` (PC pill/sheet/reconnect banner), `FolderPicker`, `Sheet` (drag-to-dismiss bottom sheet), `back.ts` (Android back button: `pushBack(close)`), `insets.ts` (safe areas/keyboard → `--sat --sab --sal --sar --kb`), `haptics.ts`.
- **On-device** (`src/device/`): `plugin.ts` is the contract of the native `StitchDevice` Capacitor plugin (Kotlin, `android/app/src/main/java/com/stitch/mobile/device/`). `catalog.ts` lists downloadable models. `store.ts` (device info, model status, downloads, backend prefs). The phone shows up inside the normal app as: a text connector `phone-llm` (`llm.ts`, kind `device`), image recipes `phone:<modelId>` in Create → Image (`image.ts`, local job queue emitting `gen:job`), and a voice connector `phone-voice` (`voice.ts`, kind `device`). `outbox.ts` uploads results to the PC (`assets:saveBytes`) and queues them while offline. `DevicePage.tsx` is More → This phone.

## Commands
- `npm run dev` — web build on :5174. For a PC to talk to, run the desktop headless with the remote on and a dev token, then point the web build at it:
  - desktop: `STITCH_USERDATA=<dir> STITCH_REMOTE=1 STITCH_REMOTE_DEV_TOKEN=<20+ chars> STITCH_HIDDEN=1 npx electron-vite dev` (in the repo root `..`; `MSYS_NO_PATHCONV=1` in Git Bash, Windows-style paths)
  - mobile: `VITE_STITCH_PC=127.0.0.1:47847 VITE_STITCH_TOKEN=<same token> npm run dev`
  - demo content: `await window.__stitchSeed()` in the web build (dev only).
- `node scripts/shot.mjs --routes "/,/stories" --out <dir> [--size 412x915] [--setup js] [--js js]` — offscreen phone-size screenshots of the running web build (uses the desktop repo's Electron). Page URL via env `SHOT_URL` (default `http://127.0.0.1:5174/`; never put a URL on Electron's command line, and use 127.0.0.1 — `localhost` can resolve to another dev server on IPv6). `MSYS_NO_PATHCONV=1` in Git Bash.
- `npm run typecheck` — typechecks this project **and** the desktop renderer through it (packages are mapped to this project's node_modules in `tsconfig.json`).
- `npm run apk` — web build → `cap sync` → Gradle `assembleDebug` (`android/app/build/outputs/apk/debug/app-debug.apk`). `npm run apk:release` for a release build (signing via `android/keystore.properties`).
- `node scripts/icons.mjs` — launcher icons, themed icon and splash from `../resources/logo-mark.svg`.
- Android SDK: `android/local.properties` (`sdk.dir=`), JDK 21.

## Conventions
- Never fork desktop UI into this project. Phone-specific chrome lives here; page layouts get fixed in the desktop code with `max-md:` / `useCompact()` (desktop at ≥768px must not change).
- Anything the phone answers itself goes through `override`/`merge` in `src/bridge` or `src/device`, keyed on ids (`phone-llm`, `phone-voice`, `phone:` recipes, `phone-` job ids). The PC must never receive them.
- Same visual language as desktop (see `../CLAUDE.md`): glass, sunset/theme accents only, motion presets from `@/lib/motion`, animate transform/opacity/filter only.
