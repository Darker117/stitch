# Stitch mobile

Android companion for the Stitch desktop studio (this repo's root, `..`). The phone is a **remote**: every chat, story, character and generation runs on the PC and stays in its library. The phone can also **generate text, images and voice on-device** (Qualcomm NPU via QNN, GPU, or CPU); those results upload to the PC library too.

## How it works
- **Same UI as desktop.** The web layer reuses the desktop renderer source directly: Vite aliases `@/` → `../src/renderer/src` and `@shared/` → `../src/shared` (override with `STITCH_DESKTOP`). Pages, components, stores and styles are the desktop's; phone layouts are `max-md:` variants / `useCompact()` in the desktop code. Features added on desktop appear here automatically. `@mobile/` → this project's `src/`.
- **Bridge** (`src/bridge/`): `install.ts` sets `window.stitch` (the same bridge the Electron preload provides) **before** any desktop module loads. `connection.ts` is one WebSocket to the PC (`<endpoint>/api/ws`, token auth, ping/pong). A pairing holds endpoint base URLs — LAN `http://ip:47847`, Tailscale IP, and the PC's public "Access from anywhere" address (`https://…trycloudflare.com` / `https://<pc>.ts.net[:port]` / custom). It cycles through them, asks the PC's encrypted relay (`pairing.ts relayLookup`, ntfy.sh topic + AES-GCM key from pairing) after each failed round (the Cloudflare address changes when the PC restarts), and hops back to Wi-Fi when it's reachable again (`preferLocal`). `router.ts` routes every `invoke`: `override(channel, fn)` answers on the phone (return `PASS` to fall through to the PC), `merge(channel, fn)` post-processes PC results, `emitLocal` fires events. `system.ts` handles `sys:*` (phone file picker → upload to PC; PC folder browser; exports saved on the PC, offered to the share sheet). `media.ts` rewrites `stitch://` URLs to the PC's media server (`/api/f`, `/api/t` thumbnails, `/api/wp` wallpapers) — the desktop calls it through `fileUrl`/`thumbUrl`/`resolveUrl`.
- **PC side** lives in the desktop app at the repo root: `src/main/remote/` (server, pairing, devices, files) and Settings → Phone (`features/settings/PhoneSettings.tsx`). Pairing: QR (`stitch://pair?d=…`) or 6-digit code + PC address.
- **Shell** (`src/shell/`): top bar, floating tab bar (`nav.tsx`), drawer (the desktop `Sidebar`), More sheet, `JobDock` (mini-player style generation bar), `LinkStatus` (PC pill/sheet/reconnect banner — the banner shows for a few seconds, then folds into an "Offline" chip on the pill so it never blocks the app), `FolderPicker`, `Sheet` (drag-to-dismiss bottom sheet), `back.ts` (Android back button: `pushBack(close)`), `insets.ts` (safe areas/keyboard → `--sat --sab --sal --sar --kb`), `haptics.ts`. Tablets (≥600px wide) get a centred tab bar and larger icons through `min-[600px]:` variants and the `--topbar`/`--tabbar` values in `mobile.css`.
- **On-device** (`src/device/`): `plugin.ts` is the contract of the native `StitchDevice` Capacitor plugin (Kotlin, `android/app/src/main/java/com/stitch/mobile/device/`). `catalog.ts` lists downloadable models. `store.ts` (device info, model status, downloads, backend prefs). The phone shows up inside the normal app as: a text connector `phone-llm` (`llm.ts`, kind `device`), image recipes `phone:<modelId>` in Create → Image (`image.ts`, local job queue emitting `gen:job`), and a voice connector `phone-voice` (`voice.ts`, kind `device`). `outbox.ts` uploads results to the PC (`assets:saveBytes`) and queues them while offline. `DevicePage.tsx` is More → This phone: Chat / Image / Voice mini-studios, the backend picker, and the model browser (search, hardware and standard/abliterated/uncensored filters, coloured tags from `tags.tsx` — theme tokens only, "show models for other chips"). `sources.ts` turns a pasted Hugging Face repo (GGUF quants, LiteRT-LM, single-file checkpoints, ONNX SD exports), Civitai checkpoint page or direct link into custom catalog entries (`store.custom`, persisted in Preferences; `CapacitorHttp` avoids CORS), and imports files picked on the phone (`importFiles`, copied natively). The HF token is only sent to huggingface.co. **Only this phone** (`prefs.deviceOnly`, toggled via the phone-answered `phone:deviceOnly` channel from Settings → Phone or This phone): pickers list only phone models (`gen:recipes` / connector merges in `index.ts`), PC chat/voice requests run on the phone, PC image requests go to the best phone image model, video/music explain they need the PC.
- **Web search on the phone** (`src/device/web.ts`): the APK carries SearXNG (pinned in `../searxng/pin.json`) on CPython 3.13 via **Chaquopy** (Gradle plugin `com.chaquo.python`, config in `android/app/build.gradle`). Kotlin `device/web/WebEngine.kt` loads Python + SearXNG lazily (first `webStart`/`webSearch`/`webPage`, never at launch) on one thread and calls `android/app/src/main/python/stitch_phone.py` → `stitch_searx.py` (the desktop's wrapper, shared — don't fork it; wrap/monkeypatch in `stitch_phone.py`, which e.g. swaps SearXNG's `yaml.safe_load` for libyaml's C loader). Python can't be unloaded: `webStop` only marks it idle; status changes arrive as the plugin's `webStatus` event → `web:status`. `web.ts` overrides every `web:*` channel. Route (`WebRoute`, phone-local in Preferences `stitch.web.route`): `auto` (default) = the PC while the link is up, falling back to the phone when the PC can't be reached or its Stitch has no `web:*` channels, else the phone; `phone`; `pc`. `web:setRoute` never reaches the PC; phone results carry `where: 'phone'`; statuses answered here carry `route`. Safe search: request → PC `settings.web.safeSearch` → 1.
- **Native runtimes** (`android/app/src/main/cpp/`, Gradle `externalNativeBuild`, always compiled Release): **llama.cpp** for GGUF text (format `gguf`: `device/text/GgufEngine.kt` → `llama_jni.cpp`) and **stable-diffusion.cpp** for `.safetensors`/`.ckpt`/`.gguf` checkpoints (format `sd-cpp`: `device/image/SdCppEngine.kt` → `sd_jni.cpp`), next to LiteRT-LM / the ONNX pipeline; the plugin routes on `format` and keeps one text and one image model in memory. Both share one ggml built as loadable backends: `libggml-cpu-android_*.so` (ARM feature levels; `stitch_backends.cpp` loads the best-scoring one; the SVE2-only `armv9.0_1` build is excluded from the APK because it measured slower than NEON + i8mm on Tensor G3) and `libggml-vulkan.so` (loaded only when a model asks for the GPU); OpenMP (NDK `libomp.so`) threads the CPU backends. stable-diffusion.cpp compiles against llama.cpp's ggml in its upstream-ggml mode, so the whole build uses `GGML_MAX_NAME=160`; only CLIP's tokenizer is bundled (`sd_vocab.cpp`; SD 1.x/2.x/SDXL). `info().runtimes[format]` says which backends each runtime has on this phone — `GgmlSupport.kt`: the GPU is offered only on families in `MEASURED_FASTER` (none yet — ggml's Vulkan measured 1.5–8× slower than the CPU on Mali; Adreno/Xclipse unmeasured); engines fall back to the CPU (and report `backend: 'cpu'`) when it isn't offered. GgufEngine: the GGUF's own Jinja chat template (llama.cpp `common`), KV-cache prefix reuse between requests, the template's reasoning markers rewritten to `<think>…</think>` (also when the template opens the block itself), stop strings via `StopMatcher`, text over JNI as UTF-8 bytes. SdCppEngine reads `config.{taesd, vae, loras[{path,scale}], sampler, schedule, clipSkip}`. Threads: `CpuInfo` (4 for llama.cpp, 5 for sd.cpp on a 1+4+4 Tensor G3).
- **Models from anywhere**: `download` follows redirects by hand and sends the caller's headers only to each file's own host (never to Civitai/HF storage it redirects to); servers without Content-Length or Range restart the file. `importFiles` = SAF picker (`ACTION_OPEN_DOCUMENT`) → streaming copy in `ModelStore.importFiles` with `download` events, cancel via `cancelDownload`, a `.complete` manifest; files without a URL are checked by path + size in `status`.
- **Catalog**: `catalog.ts` keeps hand-tuned entries and appends `catalog.gen.ts`, generated by `npm run catalog` (`scripts/catalog.mjs`) from the specs in `scripts/catalog/{text,images,voices}.mjs`: each Hugging Face repo pinned to its current commit, every file's exact size from the tree API (answers cached in `node_modules/.cache/stitch-catalog`, `--refresh` re-reads commits, `--check` re-verifies sizes, optional `HF_TOKEN`). GGUF picks Q4_0 where it exists (ARM repacking: ~40% faster prompts than Q4_K_M on a Pixel 8a). Generated files are `[repo, commit, path, bytes, saved-as?]`; voices with `espeak` get `ESPEAK_NG_DATA` added.

## Commands
- `npm run dev` — web build on :5174. For a PC to talk to, run the desktop headless with the remote on and a dev token, then point the web build at it:
  - desktop: `STITCH_USERDATA=<dir> STITCH_REMOTE=1 STITCH_REMOTE_DEV_TOKEN=<20+ chars> STITCH_HIDDEN=1 npx electron-vite dev` (in the repo root `..`; `MSYS_NO_PATHCONV=1` in Git Bash, Windows-style paths)
  - mobile: `VITE_STITCH_PC=127.0.0.1:47847 VITE_STITCH_TOKEN=<same token> npm run dev`
  - demo content: `await window.__stitchSeed()` in the web build (dev only).
- `node scripts/shot.mjs --routes "/,/stories" --out <dir> [--size 412x915] [--setup js] [--js js]` — offscreen phone-size screenshots of the running web build (uses the desktop repo's Electron). Page URL via env `SHOT_URL` (default `http://127.0.0.1:5174/`; never put a URL on Electron's command line, and use 127.0.0.1 — `localhost` can resolve to another dev server on IPv6). `MSYS_NO_PATHCONV=1` in Git Bash.
- `npm run typecheck` — typechecks this project **and** the desktop renderer through it (packages are mapped to this project's node_modules in `tsconfig.json`).
- `npm run apk` — web build → `cap sync` → `scripts/searxng.mjs` → `scripts/native.mjs` → Gradle `assembleDebug` (`android/app/build/outputs/apk/debug/app-debug.apk`). `npm run apk:release` for a release build (signing via `android/keystore.properties`).
- `npm run native` (`scripts/native.mjs`, `--force` to redo) stages the pinned llama.cpp, stable-diffusion.cpp (library sources, non-CLIP vocabularies dropped), KleidiAI and Vulkan/SPIR-V headers into `android/.native/` (gitignored; Gradle refuses to build without its `build.json`, which also names the NDK/CMake it found). For ggml's Vulkan shaders it builds host tools in `.native/host/`: Khronos' glslang release + `scripts/native/glslc-shim.cpp` (the NDK's glslc is too old) and ggml's `vulkan-shaders-gen` (ggml-vulkan's CMake is patched to take it prebuilt), with MSVC via vswhere on Windows or `c++`; without a host compiler (or with `STITCH_NATIVE_VULKAN=0`) the runtimes build CPU-only. Bump llama.cpp and stable-diffusion.cpp together.
- On-device tests: `DeviceRuntimeTest` (androidTest) — build `:app:assembleDebugAndroidTest`, `adb install -r` both APKs and run `adb shell am instrument -w -e class com.stitch.mobile.device.DeviceRuntimeTest com.stitch.mobile.test/androidx.test.runner.AndroidJUnitRunner` (never `connectedAndroidTest`: it uninstalls the app and its models). It uses models pushed into `files/models/test-*` (see the class) and `scripts/native/test-server.mjs` behind `adb reverse tcp:8765 tcp:8765`. Benchmark with the app on screen: a locked phone keeps it off the prime core.
- `npm run searxng` (`scripts/searxng.mjs`, `--force` to redo) stages SearXNG for Chaquopy into `android/.searxng/` (gitignored; Gradle refuses to build without it): `python/` = `searx/` at the pin (web UI static files, `.po`, stubs dropped) + `stitch_searx.py`; `wheels/` = **msgspec** compiled with the NDK against Chaquopy's Python headers/libpython (Maven `com.chaquo.python:target`, no Android wheel exists) and PyPI's Android **curl_cffi** wheel with its `cffi>=2` pin relaxed to Chaquopy's cffi 1.17 (same cffi module ABI); `requirements.txt` for Chaquopy's pip (SearXNG's pins; lxml 5.3.0 and cffi 1.17.1 from Chaquopy's repo; plus `tzdata`, since Android has no zoneinfo files Python can read); a build Python 3.13 (`py -3.13` / `STITCH_BUILD_PYTHON`, else python-build-standalone in `host-python/`). Incremental: only `stitch_searx.py` is refreshed when nothing else changed. `searx.engines`/`searx.answerers` are `extractPackages` (SearXNG loads them from `.py` files).
- `node scripts/icons.mjs` — launcher icons, themed icon and splash from `../resources/logo-mark.svg`.
- Android SDK: `android/local.properties` (`sdk.dir=`), JDK 21.

## Conventions
- Never fork desktop UI into this project. Phone-specific chrome lives here; page layouts get fixed in the desktop code with `max-md:` / `useCompact()` (desktop at ≥768px must not change).
- Anything the phone answers itself goes through `override`/`merge` in `src/bridge` or `src/device`, keyed on ids (`phone-llm`, `phone-voice`, `phone:` recipes, `phone-` job ids). The PC must never receive them.
- Same visual language as desktop (see `../CLAUDE.md`): glass, sunset/theme accents only, motion presets from `@/lib/motion`, animate transform/opacity/filter only.
