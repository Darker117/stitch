# Stitch

Local-first desktop studio: Higgsfield-style image/video/audio/voice generation on the user's own GPUs (ComfyUI from Stability Matrix + a local Qwen3-TTS voice engine) paired with an AI Dungeon-style story engine (OpenAI, Anthropic, OpenRouter, Gemini, Ollama, LM Studio). Characters stay consistent across stills, video and voice.

## Stack
- Electron 44 + electron-vite 5 + Vite 7, React 19, TypeScript 7 (`tsc` is tsgo — no `baseUrl`, paths must start with `./`).
- Tailwind CSS v4 (tokens in `src/renderer/src/styles.css` via `@theme inline`), `motion` (`motion/react`) for all animation, Radix primitives via the unified `radix-ui` package, `lucide-react` icons, `zustand` stores, `react-router` 7 (hash router).

## Layout
- `src/shared/` — types (`types.ts`), IPC contract (`ipc.ts`), colour maths/palette (`theme.ts`). Imported as `@shared/*`.
- `src/main/` — main process. `ipc.ts` (`handle`, `emit`), `store.ts` (JSON document store, `db(collection)`), `settings.ts` (settings + encrypted secrets), `protocol.ts` (`stitch://local/<path>` file serving with Range support; `stitch://wp-<id>/` for sandboxed Wallpaper Engine web wallpapers).
  - `services/comfy/` — ComfyUI client, built-in recipes (`recipes.ts`), job queue/routing (`jobs.ts`), managed ComfyUI processes per GPU (`process.ts`), GPU layout (`../gpu.ts`).
  - `services/llm/` — streaming chat for OpenAI-compatible, Anthropic and Ollama.
  - `services/voice/`, `services/editor.ts`, `services/wallpaper.ts`, `services/skills.ts`, `services/assets.ts`, `services/system.ts`, `services/connectors.ts`.
  - `services/wallpaper.ts` + `services/wallpaper/` — Wallpaper Engine. Scenes: `pkg.ts`/`tex.ts`/`lz4.ts`/`png.ts` read `scene.pkg` (or loose files) and decode `.tex` (DXT1/3/5, RGBA, R8, RG88, embedded JPG/PNG/MP4) to PNGs; `scene.ts` compiles scene.json + models/materials/effects/shaders (looked up pkg → folder → effect folder → the user's WE `assets/`) into `SceneData` (`@shared/wallpaper`, bump `SCENE_FORMAT` when its shape changes; `mdl.ts` reads puppet meshes in their rest pose), run in `compile.worker.ts`, cached in `<userData>/wallpapers/<id>/` by `scenes.ts`. `shader.ts` inlines includes, evaluates combos and reads the uniform annotations. Web wallpapers get WE's JS API from `protocol.ts wallpaperShim` (user properties, fps, audio bands forwarded from the window, pointer, media stubs); `allowWallpaperAudio` grants Stitch's own window loopback audio (`lib/wallpaper-audio.ts`, only while an audio-reactive wallpaper asks and Settings allows). `workshop.ts` is the Steam Workshop: keyless search via the public browse page's embedded JSON, details via `GetPublishedFileDetails`, "download" = `steam://openurl/…` in the Steam client (never a Steam login) + a folder watcher emitting `wallpaper:download`; `STITCH_WORKSHOP_DRYRUN=1` / `STITCH_STEAM_DIR` for dev tests.
  - `services/web/` — web search for text models (`web:*` channels, `settings.web`): runs the bundled SearXNG (`<repo>/resources/searxng` in dev, `process.resourcesPath/searxng` packaged) as `python -I stitch_searx.py serve` on a free loopback port with a per-start token. Starts on the first `web:search`/`web:page`, stops after 15 idle minutes, restarts with backoff after a crash, is killed (process tree) on quit and exits by itself if Stitch dies (it watches stdin). Settings, caches and bytecode live in `<userData>/searxng`; log in `<userData>/logs/searxng.log`.
- `searxng/` — `pin.json` (the SearXNG commit both apps ship) and `stitch_searx.py`, the wrapper shared with the phone app (Chaquopy, in-process): `configure(data_dir)`, `search(req)`, `page(url)` (readable text; public http(s) only, every redirect re-checked), `serve()`; CLI `python stitch_searx.py serve|check|search|page --data <dir>`. Engines: SearXNG's defaults plus Google and Bing.
  - `remote/` — the phone remote for the Stitch Android app (`mobile/`): LAN/Tailscale HTTP + WebSocket server (default port 47847, off until the user enables it in Settings → Phone). Every `handle()`d channel and every `emit()`ted event is available to paired phones over one authenticated WebSocket (`server.ts`; `BLOCKED` lists PC-only channels). Media: `/api/f/<mediaKey>/<abs path>` (Range), `/api/t/<key>/<size>/<path>` (cached OS thumbnails), `/api/wp/<key>/<id>/…` (wallpapers), `POST /api/upload`. Files are served only from Stitch/model/library roots or library assets (`files.ts mayServe`). Pairing (`remote:pairStart` → QR `stitch://pair?d=…` v2 payload with every endpoint + relay topic/key, 6-digit code, 10 min, 5 tries, per-IP lockout) and devices (token hashes only) in `devices.ts` → `<userData>/data/remote.json`. **Access from anywhere** (`anywhere.ts`, `remote:setAnywhere`, `settings.remote.anywhere`): `cloudflare` = Cloudflare quick tunnel (cloudflared downloaded on demand to `<userData>/bin`, address changes per start, so the PC posts it AES-256-GCM-encrypted to a private ntfy.sh topic the phones read), `tailscale` = Tailscale Funnel on a free port of 443/10000/8443 (never touches other serve config; withdrawn on quit), `custom` = the user's own URL. Phones get endpoints as base URLs (LAN, Tailscale IP, public) in the pairing reply, `ready` and `endpoints` messages. `settings:update` from a phone can't change `remote` (except `background`).
  - `cluster/` — multi-PC compute (Settings → Computers, `cluster:*`, `settings.cluster`). The PC you work on is the **main**; other Stitch PCs set to **node** lend their GPUs. `discovery.ts`: nodes answer UDP "find" broadcasts on 47848 (LAN/Tailscale senders only). Linking: the main asks (`cluster:requestLink`), the node shows a 6-digit code (10 min, 5 tries, the remote server's per-IP limiter), `POST /api/node/pair` returns a token — the node keeps only its hash (`store.ts` → `<userData>/data/cluster.json`), the main keeps it encrypted (secret `cluster:<nodeId>`); revocable from both sides. Nodes answer on the phone-remote server (`node.ts`, wired with `setNodeEndpoints`; the server runs when phones are on **or** the PC is a node, and phone endpoints refuse while phones are off): LAN/Tailscale only, never through the public tunnel, Bearer token checked before any upgrade. A main gets only a fixed op table (`comfy.*`, `rpc.*`, `models`, `unlink`), `WS /api/node/tcp?to=comfy|rpc&gpu=N` (TCP relay to the node's loopback ComfyUI / rpc-server on shared GPUs; one WebSocket per TCP connection, `tunnel.ts`) and `PUT /api/node/model` (model copy, never overwrites) — never the node's IPC channels. `link.ts` (main side): reconnecting control socket, live hardware (`hardware.ts`) and service updates, local tunnel listeners. Node GPUs join `settings.gpu.remote` and `assign[work]` may be `{ node, gpu }` (voice stays local): `services/gpu.ts comfyPlan` covers both, `comfy/index.ts` makes `node-<id>-gpu<n>` connectors (`ComfyConnector.node`) whose URL is the local tunnel, so the job queue, uploads, previews, downloads and hooks work unchanged (`jobs.ts` prefers instances that have the recipe's models; a waiting job wakes a stopped node ComfyUI). Node-run ComfyUI uses ports 8290+gpu (or the node's own managed one); rpc-servers stop 1 min and ComfyUI 15 min after the last main leaves. UI: `features/settings/ComputersSettings.tsx` + `computers/`, the GPUs page, `stores/cluster.ts`.
  - `services/llama/` — Stitch-managed llama.cpp (`llama:*`, `settings.llama`). `install.ts` downloads the official Windows build from ggml-org/llama.cpp releases (newest `bNNNN` tag — `latest` has no binaries; CUDA 12.4, CUDA 13 for Blackwell GPUs on a 580+ driver, CPU without NVIDIA) plus cudart, checks GitHub's SHA-256 digests and unpacks with tar to `<userData>/bin/llama.cpp/<tag>-<flavor>/`; nodes install the main's exact tag (RPC must match). `index.ts` runs `llama-server` on 127.0.0.1 with an API key (secret `llamacpp`, handed over in a short-lived key file) and `--rpc` = local tunnels to each node GPU's `ggml-rpc-server` (loopback on the node — it has no auth). Device names come from `--list-devices` (`--rpc` must come first on the command line); order = node GPUs, then this PC; `--tensor-split` by free VRAM or `settings.llama.split`. It is the `llamacpp` text connector: starts on demand from any chat, stops if a node it uses drops and restarts when it's back. GGUFs: `<userData>/models/llm`, the models home's `LLM/`, LM Studio's folders; `llama:download` pulls from Hugging Face through the downloads manager.
- `src/preload/` — exposes `window.stitch.{invoke,on,pathForFile}`.
- `src/renderer/src/` — UI. `@/` alias.
  - `lib/api.ts` — typed `invoke`, `on`, `streamLlm`, `fileUrl(path)` (use for every local media src), `parseJsonLoose`, `errorText`.
  - `lib/llm.ts` — model selection hooks (`useLlmConnectors`, `useModels`, `defaultLlm`).
  - `lib/characters.ts` — sheet slots, `characterRefs`, `sceneImageRequest`, `animateScene` (consistency pipeline).
  - `stores/db.ts` — `useCollection(name)`, `useDoc(name,id)`, `db.put/patch/update/remove` (optimistic, synced via `db:changed`).
  - `stores/gen.ts` — jobs, recipes, ComfyUI status, model lists; `submit`, `waitForJob`.
  - `stores/settings.ts`, `stores/toast.ts` (`toast.success/error/info`).
  - `components/ui/*` — the only UI kit to use: `button.tsx` (Button, IconButton, Chip), `input.tsx` (Input, Textarea autosize, SearchField), `overlay.tsx` (Dialog, Popover, Menu/MenuItem, Select, Tooltip), `controls.tsx` (Switch, Slider, SliderField, SwitchRow, Tabs, Segmented, RadioCards), `misc.tsx` (Badge, Spinner, ProgressRing, ProgressBar, Field, EmptyState, Avatar, Surface, SectionTitle, Skeleton, StatusDot), `orb.tsx`.
  - `components/media.tsx` — AssetThumb, AssetLightbox, AssetPicker, DropZone, MediaSlot, MediaList, `importFiles`, `pickAndImport`.
  - `components/shell/*` — Background, Sidebar, JobTray, Toaster, CommandPalette, `page.tsx` (Page, PageHeader, Hero).
  - `components/shell/scene/` — WebGL2 renderer for Wallpaper Engine scenes (`SceneBackground.tsx`): draws at the display's full pixel density, image layers + the scenes' own WE effect shaders in texture space, compose layers, keyframe animation, parallax, CPU particles (`particles.ts`), bloom. `glsl.ts` + `repair.ts` turn WE's GLSL/HLSL dialect into GLSL ES 3.00 and repair lines the driver rejects. Settings → Appearance → Wallpaper Engine has My wallpapers / Discover (`features/settings/wallpaper/`).
  - `features/<area>/` — one folder per section; routes live in `App.tsx`.
  - `features/characters/studio/` — **Character Studio**: node workflows (`@xyflow/react`) saved in the `flows` collection (`CharacterFlow`). `graph.ts` is the node catalogue (ports typed text/image/model/character/voice, `SPECS`, `valueOf`/`inputsOf`/`signature`), `run.ts` runs them (Portrait/Edit render through `useGen().submit` with `origin: { type: 'flow' }`, Character saves to the cast, Sheet calls `generateSheet` with the chosen edit model + LoRA stack; runs survive closing the page and `resumePending` picks up queued renders), `templates.ts` the starter workflows, `nodes.tsx` the node cards, `Studio.tsx` the canvas (desktop) / step list (phones), `StudioPage.tsx` the full-screen route `/characters/studio`. Characters → Generations groups character generations by character (`Generations.tsx`; sheet panels stay on sheets); the Generate page feed leaves out `character`/`flow` jobs.
  - `lib/web.ts` — the `web_search` / `open_page` tools every text model gets in chat (`features/create/agent.ts`) while `settings.web.enabled`; Skills → Web search (`features/skills/WebSearchSkill.tsx`) shows status, settings and a test search. Models without a tool channel (the phone's on-device model) get the tools described in the prompt and answer with `<tool_call>` lines (`extractTextToolCalls`).
  - `features/stories/engine/scripts/` — AI Dungeon-compatible story scripts: `sandbox.worker.ts` (fresh hardened worker per hook run, 1.5 s timeout), `runtime.ts` (AID globals ⇄ adventure cards/actions/`scriptState`), `play.ts` (Input/Context/Output hooks used by `usePlay`/`turn.ts`), `builtin/` (bundled MIT scripts with their LICENSE), `api.ts` (stable entry points + `AID_SCRIPTING_GUIDE` for other features). UI in `features/stories/components/scripts/`.

## Conventions
- Every IPC channel is declared in `src/shared/ipc.ts` (`IpcInvoke` / `IpcEvents`) and registered with `handle()` in main. Add channels with a small targeted edit; never rewrite the file.
- Persisted domain data goes through the document store collections in `CollectionMap` (`types.ts`); UI reads with `useCollection`/`useDoc` and writes with `db.*`.
- Generation always goes through `useGen().submit(GenRequest)` → main job queue. Set `origin` so results attach to their source (character sheet slot, adventure action) even if the UI is closed.
- Local media is referenced by asset id; render with `fileUrl(asset.path)`.
- Model "thinking" never reaches reply text: `services/llm/think.ts` splits `<think>` blocks and native reasoning fields in the main process; `streamLlm(req, onText, onReasoning)` / `LlmResult.reasoning` carry it separately. Show it only behind a collapsed "Show thinking" toggle (`ThinkingBlock` in `features/create/Messages.tsx`).
- **The phone app reuses this renderer** (Vite alias from `mobile/`), inside its own shell and with `window.stitch` backed by the remote link. So: every page must also work at phone width — use `max-md:` variants (or `useCompact()` from `lib/platform.ts` when structure must change) and never change the desktop look at ≥768px. Load local media only through `fileUrl`/`thumbUrl`/`resolveUrl` (never hand-build `stitch://` URLs) and pick files only through `sys:pickFiles`/`pickAndImport` (the phone swaps in its own picker + upload). `window.stitch.pathForFile` returns '' on the phone. Connectors/recipes with ids `phone-llm`, `phone-voice`, `phone:*` and kind `device` are answered by the phone and never reach main.
- Glass surfaces read `--panel`, `--panel-strong`, `--glass-blur` (set by `applyTheme` from `theme.glass`/`theme.glassBlur`, `-1` = automatic). Media backgrounds (wallpapers) get airier glass automatically and `html[data-bg='media']`; don't hard-code panel opacities on large surfaces. On phones `applyTheme` thickens the glass and the phone app lifts `--fg-2`/`--fg-3` for legibility (`mobile/src/mobile.css`); the phone shell's page wash reads `--phone-wash`.

## Visual language (non-negotiable)
- Sleek dark "AI chat" styling: near-black, glass panels (`glass`, `glass-strong`), 1px `border-line`, small type (12–13px body, `label-caps` for field labels), pill chips, generous rounding (10–20px).
- Accents come from the theme tokens (`--accent`, `--accent-2`, `bg-grad`, `text-grad`) — the sunset palette by default or colours picked from the user's wallpaper. Never hard-code other accent colours; `sunset-*` tokens are available for illustration.
- Motion everywhere, always smooth: use presets in `lib/motion.ts` (`spring`, `springSoft`, `page`, `pop`, `rise`, `stagger`), `layoutId` for moving highlights, `AnimatePresence` for enter/exit. Animate only transform/opacity/filter.
- Story reading surfaces use the serif (`font-serif`, IBM Plex Serif).

## Commands
- `npm run dev` — run the app with hot reload.
- `npm run typecheck` — typecheck main + renderer.
- `npm run searxng` — build the web-search bundle `resources/searxng/` (gitignored, ~94 MB): portable CPython 3.13 (python-build-standalone, pinned in `scripts/searxng.mjs`) + SearXNG at `searxng/pin.json` + its requirements (+ `tzdata`), trimmed and smoke-tested. Incremental (always refreshes `stitch_searx.py`); `--force` rebuilds. `dist`/`dist:publish` run it first. Without it, `web:status` reports `missing`.
- Screenshots for visual checks (dev only): `STITCH_CAPTURE=<dir> STITCH_USERDATA=<dir>/profile STITCH_ROUTES="/,/stories" STITCH_CAPTURE_QUIT=1 npx electron-vite dev` writes `shot-N.png` per route (`STITCH_CAPTURE_DELAY` ms per route, default 2500). `STITCH_USERDATA` isolates the profile so test runs never touch real data; several capture runs can happen at once. **In Git Bash prefix the command with `MSYS_NO_PATHCONV=1`**, otherwise MSYS rewrites `STITCH_ROUTES="/"` into `C:/Program Files/Git/` and you get a bogus 404. `STITCH_DEBUG_JS="<expr>"` logs the expression's value (from the renderer) before and after each capture.
- Phone remote in dev: `STITCH_REMOTE=1 STITCH_REMOTE_DEV_TOKEN=<20+ chars> [STITCH_REMOTE_PORT=47847]` pre-pairs a token for the mobile web build; `STITCH_REMOTE_DEV_PAIR=1` opens a pairing window at launch and logs its `stitch://pair` link (pair a real phone with `adb shell am start -a android.intent.action.VIEW -d "<link>"`); `STITCH_HIDDEN=1` runs the dev app without showing a window. See `mobile/CLAUDE.md`.
- Main + node on one PC: run a second dev instance as the node with its own `STITCH_USERDATA` whose `data/settings.json` has `cluster.role: "node"` and another `remote.port` (plus `STITCH_HIDDEN=1`); `STITCH_NODE_DEV_LINK=1` opens its link window at launch and logs the code. Drive the main through the phone dev token (`STITCH_REMOTE=1 …`). Give each profile its own `libraryDir` so test output stays out of `Documents\Stitch`.
- `npm run dist` — build the Windows installer (electron-builder, NSIS). The wizard's dark theme lives in `resources/installer.nsh` (MUI2 defines + page hooks; warnings are errors) with art from `npm run icons`.
- `npm run release` — bump the patch version, tag and push; `.github/workflows/release.yml` builds and publishes the GitHub Release that installed apps update from (`services/updater.ts`, electron-updater, Settings → Updates). Never hand-edit the version or push tags that don't match package.json. Test the updater from a dev run with `STITCH_UPDATE_DEV=1` + a `dev-app-update.yml` (generic provider) — dev runs never install on quit.
- Brand: the source artwork is `resources/brand/stitch-logo.png` (unicorn mark + plum "stitch" wordmark). `scripts/trace-logo.py` (run with any Python that has opencv + pillow, e.g. ComfyUI's venv) regenerates `components/shell/logo-paths.ts`, `resources/logo-*.svg` and `resources/icon.svg`; then `npm run icons` rebuilds the PNG/ICO/installer art. Use `LogoMark` / `Wordmark` / `LogoLockup` from `components/shell/logo.tsx` — never an `<img>` of the PNG.

## Environment notes
- ComfyUI usually comes from Stability Matrix, e.g. `C:\Users\<you>\Documents\StabilityMatrix\Data\Packages\ComfyUI` (found by `sys:detect`). Stitch-managed instances use ports 8190+; 8188 is left for a ComfyUI the user runs themselves.
- Multi-GPU example: an RTX 4090 (24 GB) + RTX 3060 (12 GB). With `CUDA_DEVICE_ORDER=PCI_BUS_ID`, nvidia-smi indices match `--cuda-device`.
